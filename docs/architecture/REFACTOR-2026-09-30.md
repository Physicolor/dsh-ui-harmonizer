# dsh-ui-harmonizer — 架构重构与对抗性审查（2026-09-30）

> 本次改动只有一个目标：把这个「对 DSH 本体 + 对每个社区插件做针对性优化」的插件，按**目标**重新组织代码——本体规范一个目录、每个社区插件各自一个目录、自有 UI 与通用基础设施各归其位——同时消除巨石文件与死代码。
>
> 硬约束：**构建产物行为不得回退**。CSS 规则与层叠顺序用 `scripts/tools/css-baseline.mjs` 逐字节校验（重构只搬不改），运行时行为用 `scripts/verify-frame-track.cjs` 与设置页检查复核。

## 1. 目标目录结构（定稿）

```
src/client/
  index.ts                    组装根：只做注解式挂载，不放实现
  core/                       与 DSH、与任何插件都无关的基础设施
    dom/                      font-probe、layout-container、observer 工具
    react/                    use-mirrored、use-popover-position
    state/                    持久化模型 + 应用/回滚
    contract/                 Harmony Contract（变量 / 材质 / 服务）
    i18n.ts
  harness/                    针对 DSH 本体的规范化与修补
    css/                      本体覆盖样式（按表面分片，保持层叠顺序）
    controls/                 官方控件 recipe 复刻（Segmented/Switch/Stepper/SettingsRow）
    settings-header/          设置页表头骨架 + 规范器
    conversation/             宽度通道、正文排版、列轨道动画
    chrome/                   header / tabs / sidebar / menus 规范化
    doctor/                   兼容性审计引擎与页面（审计对象含本体）
  plugins/                    每个社区插件一个目录，目录名 = 包名
    <plugin-package-name>/
      README.md               这个插件是谁、我们替它修了什么、证据在哪
      adapters.ts             文本/结构适配
      <name>.module.css       仅为它而写的覆盖样式
  self/                       本插件自己渲染的 UI（设置行、Doctor 页、圆角卡片）
```

判据（一条，避免将来再混）：

- 删掉这个插件后，某段代码的存在理由只与 **DSH 本体**有关 → `harness/`；
- 只与**某个第三方插件**的输出有关 → `plugins/<包名>/`；
- 只与**本插件自己画的东西**有关 → `self/`；
- 与上面三者都无关、可移植 → `core/`。

## 2. 审计报告（独立 subagent，只读）

### 2.1 React 层（`components.tsx` / `settings-page.ts` / `card-overlay.tsx` / `doctor-view.tsx`）

- 这四个文件里**没有任何 plugin:<包名> 资产**——社区适配全部落在 `enhancer.module.css` 与 `adapters.ts` / `harmony.ts`。这本身就是当前目录把三种东西混在同一层的证据。
- `SliderControl`（components.tsx:215–239）与 `enhancer.module.css:575–606` 是零引用死代码。
- 五处一字不差的「props → local state 镜像」（79/100/223/254/312）应抽 `core/react/use-mirrored.ts`。
- `getFontLabel` 是未使用导入（components.tsx:22）。
- FontSelector 菜单用 inline `style.background` 手写 hover，而 CSS 里根本没有 `.uitw-menu-item` 落点。
- `card-overlay.tsx` 1Hz `setInterval(measure)` 是永久税；`doctor-view.tsx` 的 `busy` 是同步函数里的死分支；`settings-page.ts` 的 `signature` 用文本长度导致同长度标题不更新。
- 详见下方「逐条问题」章节（实施时逐条核对）。

### 2.2 运行时层（`index.ts` / `state.ts` / `harmony.ts` / `i18n.ts` / `frame-track.ts`）

- `state.ts` 一身六职：状态模型、自持持久化、**产品宽度通道**、字体 token 发布、root 变量写入、内联属性的生命周期。后两者的清理边界靠手抄，已经漏掉 `--dsh-chat-user-width`。
- `index.ts` 的 11 段挂载里，**三处不可逆**：会话 tabs 搬迁、底部 workbench toggle 落位（都只 `observer.disconnect()`，不搬回）、文本适配（只摘标记、不还原文案，且 React 认为"文本没变"不会重写）。
- **契约变量说谎**：`--enhc-sidebar-scale` 在 `harmony.ts` 定义、README 公开，但全仓没有写入者（`state.ts` 写的是 `--enhancer-sidebar-scale`）。
- **better-sidebar 迁移做了一半**：0.19.0 起该插件不再发布 `--dsh-sidebar-width`，JS 侧的同步已删，但 CSS 里仍有大量 `.nArs4W_*` 规则并读这个变量（回退 0）——前缀统计：`nArs4W_` 35 处、`dsx-` 16 处、`V1MMBW_` 11 处、`data-genui` 15 处、`cc-toggle` 2 处、`uitw-` 30 处、`enhc-` 44 处。按「每个插件一个目录」归档后，死活的判断可以逐插件做。
- 编码损坏（mojibake，P6）：`doctor.ts` 注释、`enhancer.module.css` 的 `对话 <-> 轨迹` 与 `─`、`README.zh-CN.md` 若干行。
- 发布面缺陷（P15）：`package.json` 的 `types`/`files` 指向 `lib/types/**`，但 `tsdown.config.ts` 两个配置都是 `dts: false`，且没有任何脚本调用 `tsc` —— 类型入口指向不存在的文件。

### 2.3 脚本目录（`scripts/`，55 个脚本 + `lib/`）

- **git 只跟踪 1 个**（`verify-glide.cjs`），其余 54 个 + `lib/` 全是 untracked —— 重组没有历史负担。
- 11 个 `apply-*` 是一次性文档/CSS 改写（多数编码的是已被推翻的设计，例如 `enhc-page-head`、`data-enhc-gap`）；4 个 `fix-*` + `normalize-lf` 是一次性修复；18 个探针仍以旧端口 `3080` 为默认；`probe-diag.mjs` 写死了不存在的 `chromium-1243`。
- 仍值得留作回归的：`verify-frame-track.cjs`（唯一能跑的端到端回归）、`probe-header-geometry` / `probe-settings-headers` / `probe-menu-anchor` / `probe-menus-e2e` / `probe-menu-spacing` / `probe-dead-selectors` / `probe-harmony` / `probe-style-keeper`（多数需把默认端口改成 19387）。
- `.gitignore` 是混合编码（前 5 行 UTF-8，其余 UTF-16LE），忽略规则实际未生效（`git check-ignore` 全空）——**已修**（`scripts/pw-tmp/` 等现在生效）。

## 4. 本轮实测确认并修掉的真缺陷

| 缺陷 | 证据 | 修法 |
|---|---|---|
| 菜单样式**从未生效** | live DOM：菜单容器 class 是 `_surface_ri079_1 _list_4ub78_7 _denseList… _portal…`，`role="menu"` 在**同一元素**上；原选择器 `[role='menu'] [class^='_list_']` 是「后代 + 前缀」双重失配 | 改 `[role='menu'][class*='_list_']`（同元素 + 包含）；修后实测 `min-width 218px / padding 4px / item min-height 40px` 全部生效 |
| 侧栏「新会话」与字标规则从未生效 | 元素是多类（`_brand _wide`）→ `[class$='_brand']` 命中 0，`[class*='_brand']` 命中 4（含 3 个同前缀兄弟） | `[class*='_x']:is([class$='_x'], [class*='_x '])`（词边界对）；字标那条最终**删除**（下一条） |
| 字标被拉伸 7.6 倍 | 上面那条修好后 `svg{width:182px}` 首次生效，而 0.2 把字标拆成鲸鱼（`viewBox 0 0 23.16 17.04`，固有 24×17.66）与 HARNESS 徽章（156×24）两个 svg → 鲸鱼被拉成 182×24 | 删声明 + 墓碑注释「字标固有比例不属于我们」；实测第一个 svg 恢复 `24×17.66` |
| `menu-anchor` 会改错官方弹窗 | 官方设置按钮 `aria-haspopup="dialog"` 且在整个设置对话框打开期间 `aria-expanded="true"`，而它就在 `settings.trigger` seat 内 → 任何新菜单被钉成该按钮宽度 | 收紧为 `[aria-haspopup='menu'][aria-expanded='true'], [aria-haspopup='true'][aria-expanded='true']`（排除 dialog） |
| Doctor 报告数字是 `[object Object]` | `DoctorReport.rules` 里 `deadInThisView` 声明两次（number + `RuleRow[]`），返回字面量也写两次 | 数组改名 `deadRowsInThisView` |
| 契约变量说谎 | `--enhc-sidebar-scale` 有定义、README 公开，实现只写 `--enhancer-sidebar-scale` | `core/apply.ts` 用 `VARS.*` 写契约名并保留旧名（27 处样式仍读它），清理清单收敛到一处常量表 |
| Doctor 一条死规则 + 一条错归属 | `\.(?:eGUBIq\|Pz1RTq)_` 在已装 `dshmarket` 全库 0 命中；`data-dsh-*` 是**产品自己**的命名空间（`data-dsh-automatic-focus`） | 删死规则；`data-dsh-*` 改登记为 `harness (product)` |
| OpenCode 链路无条件拉取 → 503 刷屏 | 用户 rail 里没有任何 OpenCode 组件、key 也已删除，collector 仍旧每轮请求 `/api/opencode-usage`（未配置时 host 返回 503） | collector 增 `hasConsumer(source)`：只有**已安装**组件声明了该 `source` 才请求；单 key 路由不再请求（从多 key 结果派生）；host 侧未配置改 `200 + {configured:false}`。实测 `failed: []` |
